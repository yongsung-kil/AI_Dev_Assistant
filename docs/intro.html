ai-assisted-dev

기존 소스코드와 문서가 있는 프로젝트에 설치하는 Claude Code 플러그인. Claude가 코드를 읽어 프로젝트 프로파일을 만들고, 그 프로파일을 바탕으로 문서화, 논문과 특허 조사, 아이디어 적용 실험, 효율화와 안정성 검사, 파라미터 최적화, 작업 관리를 한다.

무엇인가

프로파일이 정본

코드를 매번 넓게 읽는 대신 다섯 문서(개요, 구조, 교체 지점, 보유 기법, 제약)를 읽는다. 언어와 무관한 낱말로 적혀 C++, Python, Verilog 프로젝트에 같은 절차가 돈다.

스킬은 절차서

스킬 17개가 각각 한 가지 일의 절차를 담는다. 읽을 것이 많은 단계는 읽기 전용 작업자(에이전트)에게 나눠 준다.

기록이 남는다

작업은 _pm/에, 결정은 판정요청 문서에, 실험은 실험로그에, 지식은 위키에 쌓인다. 대시보드가 이것을 한 화면에 보인다.

설치 없이 돈다

스크립트는 Python 표준 라이브러리만 쓴다. html은 정적 파일이라 사내망에서도 열린다.

빠른 시작

  1. 설치한다. claude plugin marketplace add yongsung-kil/AI_Assisted_Dev 뒤 claude plugin install ai-assisted-dev@ai-assisted-dev. 개발 중이면 claude --plugin-dir ./plugin.
  2. 프로젝트 루트에서 Claude Code를 열고 /ai-assisted-dev:onboard를 부른다. 탐색 작업자 4명이 코드를 읽고 docs/profile/ 다섯 문서, CLAUDE.md, _pm/이 생긴다.
  3. docs/profile/을 읽고 틀린 곳을 고친다. "미확인"으로 남은 칸을 채운다.
  4. /ai-assisted-dev:dashboard로 현황 페이지를 만들고 dashboard/index.html을 연다.
  5. 필요한 스킬을 골라 쓴다. 다음 세션부터는 시작할 때 _pm/TODO.md 요약이 자동으로 들어온다.

흐름

1onboard

프로파일, CLAUDE.md, _pm

2explore, wiki

탐색 문서, 결정과 기술 문서

3dashboard

현황 한 화면

4paper-search, screen, analyze

논문과 특허 수집, 선별, 분석

5idea-apply

교체 지점에 붙여 실험, 기록

6speed-opt, robustness, param-opt

효율화, 안정성, 파라미터

plan, review, debug, test-design은 어느 단계에서나 부른다. pm과 doc-check는 모든 단계가 쓴다.

프로파일

문서담는 것누가 쓰는가
overview.md문제 정의, 입력과 출력, 성능 지표, 실행 환경모든 스킬
structure.md모듈 지도, 호출 관계, 데이터 흐름explore, paper-analyze의 모듈 대응
replacement_points.md새 기법을 끼워 넣는 자리와 절차idea-apply
techniques.md이미 가진 기법paper-screen의 "이미 있음" 판정
constraints.md변경 금지 대상, 기밀 규칙, 용어모든 스킬

규칙: 코드를 직접 읽고 확인한 것만 적고 근거(파일:줄)를 붙인다. 모르면 "미확인". 코드가 바뀌면 프로파일을 먼저 고친다.

스킬 17개

관리 (3)
pm

작업 등록, 진행 메모, 완료 처리, 판정요청. 변경 등급 Safe, Review, Decision.

doc-check

줄표와 가운뎃점, 깨진 링크, 금지 낱말을 찾고 문장을 다시 쓴다.

dashboard

TODO, 완료, 결정 대기, 아이디어 현황, 실험, 문서 지도를 정적 html로.

문서화 (3)
onboard

프로젝트를 읽어 프로파일과 뼈대를 만든다. 다시 돌리면 바뀐 모듈만 고친다.

explore

관점 4개로 병렬 탐색하고 4개 관점으로 교차 검증해 이해 문서를 만든다.

wiki

대화, 커밋, 완료 작업, 탐색 문서에서 결정, 시도, 자산, 기술 문서를 뽑아 쌓는다.

조사 (3)
paper-search

arXiv API와 브라우저 내보내기 CSV(IEEE Xplore, Google Patents)로 수집. 같은 논문은 한 번만.

paper-screen

초록만 보고 기준서대로 in과 out. 작업자 병렬 판정, 무결성 검증 뒤 기록.

paper-analyze

전문을 읽어 고정 선택지 분류표, 10줄 요약, 모듈 대응, JSON. 카탈로그 생성.

실험과 최적화 (4)
idea-apply

접수, 지표 계획, 교체 지점에 붙이기, 기준 실험과 비교, README와 실험로그와 현황표 기록.

speed-opt

결과를 바꾸지 않는 효율화. 점검표, 한 항목 = 한 커밋, 항목 문서, 결과 동일성 근거.

robustness-check

안정성 검사. 항목 풀에서 고르고 재현, 영향 범위 분석, 수정, 회귀 테스트.

param-opt

평가 명령과 파라미터 공간을 설정하면 최적값을 찾는 표준 라이브러리 최적화기.

절차 (4)
plan

작업자 4명이 재료를 모으고 취합, 검토계획, 검토 세 라운드로 실행 계획을 확정.

review

관점 도출, 분석, 검증 세 라운드. 거짓 양성을 거르고 최종 보고 한 번.

debug

가설 4개를 병렬 추적하고 반증, 영향 범위, 수정 방향, 대안 원인으로 교차 검증.

test-design

관점별 테스트 케이스 도출과 교차 검증. P0부터 P3까지 우선순위.

에이전트와 자동 실행

이름역할도구
explorer한 관점에서 코드를 읽고 근거를 붙여 보고Read, Grep, Glob
paper-reader논문 1편과 프로파일만 읽고 판정이나 분석Read, Grep, Glob
reviewer변경 범위를 한 관점에서 읽고 파일:줄과 심각도로 보고Read, Grep, Glob, git diff
자동 실행언제무엇을
TODO 확인세션 시작_pm/TODO.md에 확인 시각을 적고 미완 작업 요약을 문맥에 넣는다
문서 검사md 파일을 고친 뒤줄표와 가운뎃점을 찾아 경고만 낸다 (막지 않는다)

작업 관리와 대시보드

_pm/TODO.md

작업 목록. 항목마다 상세 폴더 링크와 하위 단계 상자. 대시보드의 진행 중 카드가 된다.

_pm/tasks/

작업마다 폴더 하나. 태스크 문서(목적, 배경, 설계, 수정 대상, 안전성 체크리스트, 미결정)와 판정요청.

판정요청

사용자만 정할 수 있는 것을 예시와 선택지와 권고로 묻는 문서. % 줄에 번호로 답한다.

_pm/DONE.md

완료 이력. 작업 단위 변경 이력이 된다 (커밋 단위가 아니다).

자주 묻는 것

다른 언어나 하드웨어 설계 프로젝트에도 되는가

된다. 프로파일은 언어와 무관한 낱말(모듈, 인터페이스, 교체 지점, 신호)로 적고, onboard가 언어별 탐색 방법을 고른다. 하드웨어 설계면 모듈 계층과 신호 인터페이스, 클록과 리셋을 관점에 더한다. 안정성 검사의 항목 풀에는 리셋 값, 비트 폭, 클록 영역 넘김이 있다.

교체 지점이 없는 코드는

idea-apply가 붙이기 전에 멈추고 "교체 지점 만들기" 작업을 등록한다. 프로파일 replacement_points.md에 후보 자리가 "만들어야 함" 상태로 적혀 있다.

사내망에서 바깥이 막혀 있으면

arXiv 검색도 브라우저에서 하고 내보내기 CSV를 들여온다. html은 외부 자원을 쓰지 않으므로 그대로 열린다.

다른 플러그인의 계획이나 리뷰 스킬과 겹치면

한쪽을 끈다. claude plugin disable <이름> 또는 /plugin에서 끈다. 이 플러그인의 절차는 한국어와 _pm/ 규약에 맞춰져 있다.

macOS나 Linux에서 자동 실행 오류가 뜨면

스크립트를 python 명령으로 부르기 때문이다. python이 python3를 가리키게 연결하면 사라진다.
