# 안정성 점검표 (잘못된 입력과 경계 조건에서 무너지지 않는가)

> 목적: 코드가 잘못된 입력, 경계 조건, 자원 한계에서 죽거나 틀린 값을 내지 않게 한다.
> 원칙: 한 항목 = 한 커밋. 효율화 항목과 커밋을 섞지 않는다 (결과가 달라졌을 때 원인을 나눌 수 있게).
> 표기: [결과 달라질 수 있음] = 고치면 이전 결과와 달라질 수 있다. 달라진다면 이전 코드가 잘못된 값을 읽고 있었다는 뜻이므로 새 값이 맞다. 그 근거를 항목 문서에 적는다.
> 진행: 재현(테스트나 입력) → 영향 범위 분석 → 수정 → 회귀 테스트 → 사용자 검토 → 커밋.

---

## 항목 풀 (프로젝트에 맞는 것을 아래 절로 옮긴다)

| 분류 | 무엇을 보는가 | 어디서 자주 생기는가 |
|---|---|---|
| 배열 범위 밖 접근 | 인덱스가 길이를 넘는 읽기와 쓰기, 길이 0 배열 | 루프 상한이 상수인 곳, 가드 밖 함수 |
| 정수 넘침 | 곱셈과 누적 합, 부호 있는 형과 없는 형 섞임 | 합계, 카운터, 인덱스 계산 |
| 초기화 안 된 값 | 선언만 하고 읽는 변수와 배열 | 조건 분기 뒤, 재사용 버퍼 |
| 0으로 나눔 | 분모가 0이 되는 입력 | 비율, 평균, 정규화 |
| 고정소수점 포화와 자름 | 표현 범위를 넘는 값의 처리 | 양자화, 누적, 시프트 |
| 재현성 | seed와 실행 순서에 따라 결과가 달라지는가 | 난수, 병렬 처리, 사전 순서 |
| 자원 해제 | 열린 파일, 할당한 메모리, 스레드 | 오류 경로 |
| 입력 검증 | 형식이 틀린 파일, 빈 파일, 큰 파일 | 파서, 설정 읽기 |
| 리셋 값 (RTL) | 리셋 뒤 정해지지 않은 레지스터 | 상태 기계, 카운터 |
| 비트 폭 불일치 (RTL) | 대입에서 잘리는 상위 비트 | 산술 결과, 포트 연결 |
| 클록 영역 넘김 (RTL) | 동기화 없이 넘어가는 신호 | 인터페이스 경계 |
| 래치 생성 (RTL) | 조합 논리에서 모든 경우를 덮지 않는 분기 | case와 if 문 |
| X 전파 (RTL) | 정해지지 않은 값이 퍼지는 경로 | 초기화 안 된 메모리 |
