# 안정성 검사

효율화와 커밋을 섞지 않는다. 결과가 달라지면 새 값이 맞는 이유를 적는다. 스크립트는 이 스킬의 기준 폴더에서 `../../scripts/`에 있다.

## 절차

- 1. 항목 고르기. `python "<이 스킬의 기준 폴더>/../../scripts/checklist_init.py" robustness .`로 `docs/robustness/`에 점검표(항목 풀 포함)와 항목 양식을 만든다. 프로파일 `overview.md`의 언어와 환경에 맞는 분류를 항목 풀에서 골라 "이 프로젝트의 항목"에 적는다 (소프트웨어면 배열 범위, 정수 넘침, 초기화, 0으로 나눔, 포화, 재현성, 자원, 입력 검증. 하드웨어 설계면 리셋 값, 비트 폭, 클록 영역, 래치, X 전파를 더한다). 후보 위치는 explore 스킬의 "경계와 제약" 관점으로 찾는다
- 2. 재현. 항목마다 문제가 드러나는 입력이나 테스트를 만든다. 재현되지 않으면 항목 문서에 그 사실을 적고 "제외한 항목"으로
- 3. 영향 범위 분석. 고쳤을 때 타이밍, 중간 상태, 최종 결과 중 무엇이 달라질 수 있는지 사용처를 전수 추적해 항목 문서에 적는다. 달라진다면 이전 코드가 잘못된 값을 읽고 있었다는 뜻이므로 새 값이 맞는 근거를 적는다
- 4. 수정. 한 항목 = 한 커밋. 재현 입력을 회귀 테스트로 남긴다
- 5. 사용자 검토 뒤 커밋. 적용 시점이 "다른 항목을 끝낸 뒤 맨 마지막"인 항목은 그 순서를 지킨다
- 6. `docs/robustness/README.md`의 적용 이력 표를 갱신한다

## 규칙

- ㉮ 재현 없이 고치지 않는다
- ㉯ 결과가 달라질 수 있는 항목은 [결과 달라질 수 있음]으로 표기하고 효율화 항목과 커밋을 분리한다
- ㉰ 변경 금지 대상(`constraints.md`)에 걸리면 고치지 않고 판정요청으로 올린다
