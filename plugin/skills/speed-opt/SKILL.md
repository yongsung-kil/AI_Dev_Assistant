# 효율화 (실행 시간과 메모리)

결과가 같아야 한다. 한 항목 = 한 커밋. 스크립트는 이 스킬의 기준 폴더에서 `../../scripts/`에 있다.

## 절차

- 1. 후보 발굴. 프로파일 `structure.md`의 핵심 흐름과 자료 구조에서 가장 자주 도는 곳(핫루프)을 찾는다. 모르면 explore 스킬로 "특정 흐름 추적"을 돈다. 후보마다 실행 빈도와 비용을 숫자로 적는다
- 2. 점검표 작성. `python "<이 스킬의 기준 폴더>/../../scripts/checklist_init.py" speed .`로 `docs/speed_opt/`에 점검표와 항목 양식을 만들고, 후보를 항목으로 적는다. 항목마다 함수, 바꿀 부분, 방법, 결과 동일성 표기(결과 동일 보장 | 검증 필요), 위험도. 변경 금지 대상(`constraints.md`)에 걸리는 후보는 "제외한 항목" 표에
- 3. 한 번에 한 항목. 수정하고, 항목 문서(`{N-M}_{이름}.md`, 양식 item_template.md)에 왜 해야 하나, 무엇을 어떻게 바꿨나, 검증, 이식 앵커를 쓰고, 사용자 검토를 받고, 커밋한다. 다음 항목으로
- 4. 결과 동일성 검증. 같은 입력과 seed의 결과가 이전과 같은지 확인한다. 이 환경에서 빌드나 실행을 못 하면 외부 검증 위치와 방법을 항목 문서에 적고 상태를 검토 대기로 둔다
- 5. `docs/speed_opt/README.md`의 적용 이력 표를 갱신한다

## 규칙

- ㉮ 결과 동일 보장 항목만 먼저 모아 적용하고, 검증 필요 항목은 따로 커밋한다 (불일치 원인을 나눌 수 있게)
- ㉯ 잠재 버그(범위 밖 접근 등)를 발견하면 여기서 고치지 않고 robustness-check 스킬로 넘긴다. 효율화와 커밋을 섞지 않는다
- ㉰ 수정 지점이 많은 항목은 옛 이름 검색 0건처럼 누락 검출 방법을 항목 문서에 적는다
