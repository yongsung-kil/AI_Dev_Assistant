# 코드베이스 탐색

관점별 병렬 탐색과 교차 검증으로 이해 문서를 만든다. 탐색 작업자는 이 플러그인의 `explorer` 에이전트(읽기 전용)이며, 저장은 메인이 한다.

## 흐름

```
범위 확정 -> 관점별 병렬 탐색 (4) -> 취합 -> 교차 검증 (4) -> 최종 문서
```

## 1단계: 범위 확정과 작업 등록 (메인)

- ㉮ 대상을 정한다: 프로젝트 전체, 특정 모듈, 특정 흐름. 폴더 구조를 빠르게 훑어 윤곽을 잡는다
- ㉯ 목적을 정한다: 수정하기 위한 이해, 전체 구조 파악, 특정 흐름 추적, 프로파일 작성(onboard가 부를 때)
- ㉰ 기록 위치: 진행 중인 작업이 있으면 `_pm/tasks/{작업}/explore/`, 없으면 `_pm/tasks/{YYYYMMDD}_explore_{주제}/explore/`. 라운드 폴더는 `explore/r{N}_{이름}/`. `_pm/TODO.md`에 탐색 항목을 등록한다 (pm 스킬)
- ㉱ `docs/profile/`이 있으면 먼저 읽는다. 프로파일과 어긋난 것을 발견하면 최종 문서에 적는다

## 2단계: 관점별 병렬 탐색 (explorer 4명, background)

메인이 대상에 맞는 독립 관점 4개를 정해 `ai-assisted-dev:explorer` 에이전트 4명에게 하나씩 준다. 관점은 서로 겹치지 않게, 목적에 맞게, 전체면 넓고 얕게, 모듈이면 좁고 깊게 잡는다.

관점 풀 (참고. 대상에 맞게 고르거나 새로 정한다)

| 대상 | 관점 넷 |
|---|---|
| 프로젝트 전체 | 아키텍처(폴더, 모듈 분리, 계층, 진입점, 빌드), 데이터 흐름(입력에서 출력까지, 자료 구조, 상태), 컨벤션과 패턴(이름 규칙, 오류 처리, 로그, 설정, 테스트 구조), 의존성(라이브러리, 외부 연동, 버전 제약) |
| 특정 모듈 | 내부 구조(파일, 클래스와 함수 관계, 핵심 로직), 인터페이스(밖에 내놓는 것, 다른 모듈과의 의존, 호출 사슬), 상태와 자료(관리하는 자료, 상태 전이, 저장, 캐시), 경계와 제약(오류 처리, 알려진 한계, TODO와 FIXME, 기술 부채) |
| 특정 흐름 | 정상 경로(입력부터 출력까지 코드 따라가기), 오류 경로(단계마다 실패 지점과 처리), 부수 효과(로그, 이벤트, 캐시 갱신, 외부 호출), 설정과 분기(환경과 설정에 따라 달라지는 동작) |

에이전트에게 주는 것: 탐색 대상, 탐색 목적, 배정된 관점의 확인 항목 목록. 돌아온 보고는 메인이 `explore/r{N}_{이름}/agent_{A|B|C|D}.md`에 저장한다.

## 3단계: 취합 (메인)

- ㉮ 보고 넷을 이해 문서 하나로 합친다. 중복을 지우고 모순은 코드 근거가 있는 쪽을 택한다
- ㉯ 관점 사이의 연결점과 미탐색 영역을 적는다
- ㉰ 사용자에게 보이고 피드백을 기다린다. onboard 스킬이 부른 경우에는 멈추지 않고 4단계로 간다

## 4단계: 교차 검증 (explorer 4명, background)

취합 문서를 관점 넷으로 검증한다. 결과는 `explore/r{N}_{이름}/verify_{A|B|C|D}.md`.

| 작업자 | 관점 | 핵심 질문 |
|---|---|---|
| A | 사실 검증 | 문서의 주장이 실제 코드와 맞는가 (표본 대조) |
| B | 누락 탐색 | 중요한데 빠진 것이 있는가 (폴더와 파일 목록 대조) |
| C | 관계 검증 | 모듈 사이 관계와 의존 설명이 맞는가 (import와 호출 추적) |
| D | 실용성 | 목적에 비춰 이 문서로 충분한가, 더 봐야 할 것은 |

## 5단계: 최종 문서 (메인)

검증 결과를 반영해 최종 문서를 쓴다. `explore/EXPLORATION.md`에 저장하고, 같은 내용을 `docs/explore/{대상}.md`에도 둔다 (위키 tech 갈래의 원재료). TODO의 탐색 항목을 완료 처리하고 후속 작업이 있으면 등록한다. 사용자에게 보인다 (onboard가 부른 경우에는 onboard가 이어서 쓴다).

```markdown
# {대상} 탐색 결과

## 개요
(대상이 무엇이고 무엇을 하는지, 3줄 안에)

## 아키텍처
(구조, 계층, 핵심 모듈 관계)

## 핵심 흐름
(주요 자료와 제어 흐름, 입력부터 출력까지)

## 주요 컴포넌트
| 컴포넌트 | 역할 | 위치 |
|---|---|---|

## 외부 의존성

## 주의 사항
(알려진 한계, 기술 부채, 복잡한 부분)

## 프로파일과 어긋난 것
(docs/profile/이 있을 때만)

## 미탐색 영역
```

## 에이전트에게 주는 지시 (2단계)

```
탐색 대상: {범위}
탐색 목적: {수정 예정 | 전체 파악 | 흐름 추적 | 프로파일 작성}
배정된 관점: {관점 이름}
확인 항목:
- {항목}
규칙은 당신의 에이전트 정의에 있다. 보고 꼴을 지키고, 근거 경로와 줄을 붙여라.
```

## 에이전트에게 주는 지시 (4단계)

```
검증 대상 문서: {취합 문서 경로}
원래 탐색 대상: {범위}
검증 관점: {A 사실 | B 누락 | C 관계 | D 실용성}
확인 항목:
- {항목}
문서의 주장을 코드와 대조해 맞음, 틀림(근거), 빠짐(근거)으로 보고하라.
```

## 실패 처리

- ㉮ 범위가 넓어 표면 보고만 오면 하위 모듈로 나눠 다시 돌린다
- ㉯ 작업자 사이의 모순은 코드 근거가 있는 쪽을 택하고, 양쪽 다 근거가 있으면 5단계에 병기한다
- ㉰ 빈 보고는 한 번 다시 돌리고, 그래도 비면 메인이 직접 본다

## 후속 연계

- ㉮ 수정이 필요하면 plan 스킬로 계획을 세운다 (탐색 문서가 입력)
- ㉯ 문제를 발견하면 debug 스킬로 원인을 찾는다
- ㉰ 탐색 문서는 wiki 스킬이 tech 갈래로 옮긴다
