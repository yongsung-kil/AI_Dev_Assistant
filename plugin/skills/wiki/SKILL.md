# 위키 만들기와 갱신

원재료를 훑어 AI와 사람이 다시 쓸 지식을 `_wiki/`에 쌓는다. 갈래는 넷이다.

| 갈래 | 담는 것 | 판단 기준 |
|---|---|---|
| decisions | 코드와 프로젝트에 실제 반영된 결정 | "왜" 그 선택을 했는지 이유가 있다 |
| trials | 시도했지만 반영하지 않은 것 | 실패에서 배운 교훈이 있다 |
| assets | 다시 쓸 수 있는 것 (패턴, 잘못된 패턴, 프롬프트, 조각) | 다음에 비슷한 상황에서 그대로 쓴다 |
| tech | 코드가 어떻게 도는지 설명하는 문서 (알고리즘, 모듈 동작, 사용법) | 코드를 다시 읽지 않고도 동작을 안다 |

핵심 질문은 하나다. "다음에 비슷한 상황이 오면 이 기록이 도움이 되는가?" 그렇다면 승격, 아니면 기록만 하고 넘어간다. 단순 버그 수정, 오타, 의존성 판 올림, 포맷 정리, 이미 위키에 있는 결정의 반복 적용은 넘어간다.

## 실행 단계 (자동 판별)

| 단계 | 조건 | 동작 |
|---|---|---|
| 1 첫 실행 | `_wiki/`가 없다 | `python "<이 스킬의 기준 폴더>/../../scripts/wiki_init.py" .`로 뼈대를 만든다. 코드 구조, CLAUDE.md, README, `docs/profile/`, `docs/explore/`, `_pm/DONE.md`, `_pm/done/*/`, 커밋 로그 전체를 훑어 manual.md 초안, 주요 decisions, tech 문서 초안을 만든다 |
| 2 소급 | `_wiki/`가 있고 `_tracker.md`에 미스캔 원재료가 많다 | 대화 기록 파일(있을 때만), `_pm/DONE.md`, 커밋 로그를 훑어 빠진 것을 보충하고 `_tracker.md`를 채운다 |
| 3 증분 | `_wiki/`가 있고 `_tracker.md`가 최신이다 | 마지막 스캔 이후의 `_pm/DONE.md` 항목, `_pm/done/*/` 폴더, 커밋, 대화 기록, `docs/explore/` 새 문서, `_wiki/_inbox/` 대기 항목만 처리한다. 처리할 것이 없으면 "위키 최신 상태"라고 보고하고 끝낸다 |

단계 안의 흐름은 같다: 스캔 -> 병렬 수집 -> 취합과 분류 -> 병렬 작성 -> 취합과 중복 검사 -> 갱신.

## 1. 스캔 (메인)

단계를 판별하고 원재료 목록을 만든다. `_tracker.md`의 처리된 범위와 대조한다.

## 2. 병렬 수집 (explorer 에이전트 N명, background)

원재료를 출처별로 나눠 `ai-assisted-dev:explorer`에게 준다. 각 작업자는 담당 출처에서 위키화할 항목을 뽑고 갈래(decisions, trials, assets, tech, uncertain)를 제안한다. 대화 원문을 그대로 베끼지 않고 핵심만, 출처(커밋 해시, 세션 파일과 구간, 문서 경로)를 붙인다. 메인이 결과를 `_wiki/_inbox/{출처}_extract.md`에 저장한다.

## 3. 취합과 분류 (메인)

수집 결과를 합치고 중복을 지운다. uncertain은 사용자에게 묻는다. 항목별 작성 지시 목록을 만들어 사용자에게 보이고 피드백을 기다린다 (자동 진행을 지시받았으면 바로 4단계).

## 4. 병렬 작성 (일반 에이전트 N명, background)

확정된 항목을 갈래 양식(`_wiki/_templates/{decision,trial,asset,tech}.md`)에 맞춰 쓴다. 파일 이름은 `YYYYMMDD_{주제-kebab-case}.md`. 규칙: 문장은 짧게, 개조식. 용어는 원어 유지. 링크는 앞으로만(A에서 B). 대화 원문을 베끼지 않고 머리말에 출처만. 기존 문서와 겹치면 새로 쓰지 않고 갱신을 제안한다. 양식 필드가 부족하면 보고한다. 결과는 `_wiki/_inbox/{파일 이름}`에.

작성 에이전트에게 주는 지시:

```
당신은 위키 문서 작성자입니다. 아래 항목을 양식에 맞춰 위키 문서로 쓰세요.
작성 항목: {항목, 갈래, 출처}
양식: {갈래 양식 전문}
기존 문서 목록: {_wiki/ 파일 목록과 요약}
규칙: 문장 짧게, 개조식. 앞으로 가는 링크만. 원문 베끼지 않음. 겹치면 갱신 제안. 필드 부족하면 보고.
```

## 5. 취합과 중복 검사 (메인 + 일반 에이전트 1명)

중복 검사 에이전트가 새 문서와 기존 `_wiki/` 문서의 겹침을 찾아 병합안(어느 쪽에 흡수, 이유)을 `_wiki/_inbox/dedup_report.md`에 쓴다. 메인이 반영하고 사용자에게 보인다 (자동 진행이면 바로 6단계).

## 6. 갱신 (메인)

- ㉮ 새 문서를 갈래 폴더에 옮긴다
- ㉯ 갈래 MOC에 항목(링크와 한 줄 요약)을 더한다. 문서 상태가 바뀌면(Accepted에서 Superseded) MOC의 상태를 고친다. 최상위 MOC.md는 갈래 MOC가 바뀔 때만 고친다
- ㉰ `_tracker.md`에 처리한 출처와 범위를 적고 `last_scan`을 `date '+%Y-%m-%d %H:%M:%S'`로 갱신한다
- ㉱ 프로젝트 설명이 바뀌는 결정이 있으면 manual.md를 고친다
- ㉲ `_inbox/`의 처리한 파일을 지우고 결과를 요약해 보고한다

## 품질 유지

- ㉮ 실행 때마다 고아 문서(어디서도 가리키지 않음), 오래된 문서(last_verified가 코드 변경보다 앞섬), 깨진 링크를 찾아 보고한다
- ㉯ 양식 필드가 부족하거나 남으면 보고한다
- ㉰ tech 문서는 근거 파일이 바뀐 커밋이 있으면 "다시 대조 필요"로 표시한다
