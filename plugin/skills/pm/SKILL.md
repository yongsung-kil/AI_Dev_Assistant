# 프로젝트 작업 관리

작업의 등록, 진행, 완료, 결정 요청을 `_pm/` 폴더로 한다. 스크립트는 이 스킬 폴더의 두 단계 위 `scripts/`에 있다.

## 1. 폴더

```
_pm/
├── TODO.md      작업 목록 + Claude 마지막 확인 시각
├── DONE.md      완료 이력 (최근 것이 위)
├── tasks/       진행 중인 작업의 문서 (비어 있으면 진행 중 작업 없음)
└── done/        완료된 작업 문서 ({YYYYMMDD}_{주제}/)
```

`_pm/`이 없으면 먼저 만든다: `python "<플러그인 루트>/scripts/pm_init.py"` (프로젝트 루트에서).

## 2. 세션 시작 때

- ㉮ 세션 시작 자동 실행이 `_pm/TODO.md`의 확인 시각을 적고 미완 작업 요약을 문맥에 넣는다
- ㉯ "새 작업 추가" 절에 항목이 있으면 "작업 목록"으로 옮기고 시작할지 사용자에게 묻는다

## 3. 변경 등급

| 등급 | 대상 | 처리 |
|---|---|---|
| Safe | 로그, 주석, 포맷 | 자동 진행 |
| Review | 로직 변경, 동작 유지 의도 | 브리핑 뒤 진행 |
| Decision | 설계 변경, 영향 범위 큼 | 작업을 멈추고 사용자 확인 |

## 4. 작업 등록

- 1. `_pm/tasks/{YYYYMMDD}_{작업명}/` 폴더를 만들고 `_template/task.md`를 복사해 `{YYYYMMDD}_{작업명}.md`로 채운다 (목적, 배경, 설계, 수정 대상, 안전성 체크리스트, 미결정 사항)
- 2. TODO.md "작업 목록"에 항목을 더한다. 꼴: `- [ ] 제목` 아래에 `  - 상세: _pm/tasks/{폴더}/` 와 하위 단계 `  - [ ] 단계`
- 3. 시각은 `date '+%Y-%m-%d %H:%M:%S'` 결과를 적는다
- 4. 문서 정리처럼 단순한 작업은 폴더 없이 TODO 항목만 둔다

## 5. 진행 중

- ㉮ 커밋마다 TODO 해당 항목 아래에 진행 메모를 적는다 (하위 단계 `[x]` 또는 메모 한 줄)
- ㉯ Decision 등급이 나오면 멈추고 6절로 묻는다

## 6. 결정 요청 (판정요청)

사용자가 정해야 하는 것은 대화로 길게 묻지 않고 판정요청 문서로 묻는다. 규약은 이 폴더의 [decision_protocol.md](decision_protocol.md)이고 양식은 `_pm/tasks/_template/decision_request.md`다. 결정거리가 하나이고 선택지가 두세 줄이면 대화로 묻되 같은 차례(예시, 상황, 문제, 선택지, 권고)로 적는다.

## 7. 완료 처리

- 1. `tasks/{폴더}/`를 `done/{YYYYMMDD}_{주제}/`로 옮긴다
- 2. TODO.md에서 항목을 지운다
- 3. DONE.md 맨 위에 더한다
   ```
   ### YYYY-MM-DD 작업 제목
   요약 한 줄
   - **배경**: 왜 이 작업을 했는지
   - **변경**: 핵심 변경 내용
   - **파일**: 수정된 주요 파일
   ```
- 4. 커밋한다 (아래 8절)

## 8. 커밋

- ㉮ 시점: 작업 완료 직후. 가지는 지금 작업 중인 가지
- ㉯ 메시지: `<type>: <간결한 설명>` 뒤에 빈 줄, 변경 사항 목록. type은 feat, fix, docs, refactor, test, chore
- ㉰ 커밋 뒤 push한다 (원격이 있을 때)
