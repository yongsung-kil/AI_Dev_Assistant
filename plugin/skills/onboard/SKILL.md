# 온보딩 (프로젝트 프로파일 만들기)

프로젝트를 읽어 프로파일을 만든다. 프로파일은 다른 모든 스킬이 코드 대신 읽는 지식의 정본이다. 스크립트는 이 스킬의 기준 폴더에서 `../../scripts/`에 있다.

## 절차

- 1. 훑기. 프로젝트 루트에서 `python "<이 스킬의 기준 폴더>/../../scripts/onboard_init.py" . --summary-only`를 돌려 언어별 파일 수, 최상위 폴더, 진입점 후보, 빌드 파일, README를 받는다. README와 빌드 파일을 읽는다. 이미 `docs/profile/`이 있으면 채워진 정도를 보고 4단계에서 빈 곳만 채운다
- 2. 탐색. explore 스킬을 "프로젝트 전체, 목적은 프로파일 작성" 모드로 돈다. 관점 넷은 아키텍처, 데이터 흐름, 컨벤션과 패턴, 의존성이다. 언어가 하드웨어 설계(verilog, systemverilog, vhdl)면 아키텍처 관점에 "모듈 계층과 신호 인터페이스", 데이터 흐름 관점에 "클록과 리셋, 파이프라인 단계"를 더한다. 이 호출에서는 사용자 피드백 대기 없이 끝까지 간다
- 3. 양식 복사. `python "<이 스킬의 기준 폴더>/../../scripts/onboard_init.py" .`로 `docs/profile/` 여섯 문서, `CLAUDE.md`, `docs/usage.md`(이 프로젝트에서 플러그인 쓰는 법), `docs/adr/README.md`, `docs/explore/`를 만든다 (있는 파일은 건드리지 않는다)
- 4. 프로파일 채우기. 탐색 문서와 코드를 근거로 다섯 문서를 채운다. 문서마다 채우는 규칙은 양식의 괄호 안에 있다. 지킬 것:
  - ㉮ 코드를 직접 읽고 확인한 것만 적고 근거 파일과 줄을 붙인다. 모르면 "미확인"
  - ㉯ 언어에 기대지 않는 낱말로 적는다 (모듈, 인터페이스, 교체 지점, 신호)
  - ㉰ 교체 지점이 없으면 replacement_points.md 1절에 "없음, 만들어야 함"이라고 적고 후보 자리(기법이 갈아 끼워질 만한 함수나 모듈)를 표에 "만들어야 함" 상태로 적는다
  - ㉱ constraints.md의 변경 금지 대상은 README, 주석, 설정에서 "바꾸지 말 것"으로 읽히는 것을 모으고, 없으면 "미확인"으로 둔다
  - ㉲ 채운 뒤 양식의 괄호 안내 줄은 지운다
- 5. CLAUDE.md의 빈칸(프로젝트 이름, 한 문장, 실행 명령)을 채운다. `docs/usage.md`의 괄호 자리(프로젝트 이름, 한 문장, 실제로 있는 폴더, 실행 명령)도 채우고 괄호 안내 줄은 지운다. 이 문서는 나중에 온 사람이나 쓰는 법을 잊은 사람이 처음 여는 문서다. 사용자 프로젝트에 이미 CLAUDE.md가 있었으면 그 파일은 그대로 두고, 프로파일을 가리키는 "지식의 정본" 절만 끝에 더한다
- 6. 작업 관리. `_pm/`이 없으면 `python "<이 스킬의 기준 폴더>/../../scripts/pm_init.py" .`로 만들고, `_pm/TODO.md`에 "프로파일 검토 (사용자가 다섯 문서를 읽고 틀린 곳 표시)" 항목을 등록한다 (pm 스킬)
- 7. 검사와 보고. doc-check 스킬로 `docs/`와 `CLAUDE.md`를 검사해 0건으로 만든다. 만든 파일 목록, 못 채운 항목("미확인"으로 남은 것), 프로파일과 코드가 어긋나 보인 곳을 보고한다

## 다시 돌릴 때

프로파일이 이미 있으면 1단계의 요약과 최근 커밋을 보고 바뀐 모듈만 다시 탐색해 해당 절을 고친다. 사용자가 채운 문장은 근거가 틀리지 않는 한 그대로 둔다.
